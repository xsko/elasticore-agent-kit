# 변경 요청: 반려동물 쇼핑몰 2차
{TOOL_LINE}
이 폴더는 이미 동작하는 반려동물 쇼핑몰 프로젝트다(README.md 참고). 아래 변경을 반영한다. 기존 기능은 그대로
동작해야 한다.

- 이 PC에서 8080 포트는 다른 프로그램이 쓰고 있다. 서버를 띄워 확인할 때는 포트 {PORT}를 쓴다.
- 이 PC에서는 다른 사람의 프로그램(java 등)도 돌고 있다. 프로세스를 이름으로 종료하지 않는다. 직접 띄운 서버는
  그 서버를 띄운 방법으로(예: 백그라운드 작업을 기록해 두고) 끈다.

## 변경

1. **재고.** 품목에 재고 수량(0 이상, 필수)을 둔다. 샘플 품목에는 재고를 넣어 둔다. 주문하면 각 줄의 수량만큼
   재고가 줄고, 한 줄이라도 재고가 모자라면 주문 전체를 거부한다(409, 메시지에 품목 이름). 주문을 취소하면 재고를
   되돌린다. 관리자는 재고를 고칠 수 있다.
2. **리뷰.** 로그인한 회원이 품목에 리뷰를 단다: 별점(1~5, 필수), 내용(1~1000자, 필수), 작성 시각(서버가 정함).
   한 회원은 한 품목에 리뷰를 하나만 쓸 수 있다(두 번째는 409). 리뷰 수정·삭제는 쓴 사람만(관리자는 삭제 가능).
   누구나 품목별 리뷰 목록을 최신순으로 본다. 리뷰 응답에는 쓴 사람의 로그인 ID 가 보이고 다른 개인정보는 없다.
3. **택배사 연동.** 관리자가 주문을 배송 처리하면 택배사 API 를 불러 운송장 번호를 받아 주문에 저장한다.
   택배사 API: `POST {courier.base-url}/shipments`, 요청 `{"orderId": ..., "zipCode": ..., "city": ...}`, 응답
   `{"trackingNo": "..."}`. 택배사 주소(`courier.base-url`)는 설정 파일에 둔다. 아직 실제 택배사가 없으니, 시험용
   가짜 택배사를 이 서버 안에 `/fake-courier/shipments` 로 두고(운송장 번호는 `TRK-` + 주문 번호) 기본 설정은 그
   주소를 가리키게 한다. 택배사가 오류를 내면 배송 처리는 실패하고 주문은 PLACED 로 남는다(502).
   운송장 번호는 주문 응답에 나온다.
4. **BI 지표.** 회사 BI 도구가 쓸 수 있도록 매출(취소 제외 total 합), 주문 수(취소 제외), 객단가(매출 / 주문 수),
   회원 수의 정의를 표준 시맨틱 모델(Apache Ossie) 파일로 낸다. 관리자 매출 요약 API 도 객단가를 함께 돌려준다.
5. **한국어 오류 메시지.** 요청에 `Accept-Language: ko` 가 있으면 검증 오류(400)의 필드 메시지를 한국어로 답한다.
   없으면 지금처럼 영어.

## 끝내기 전에

- `./gradlew build` 가 성공해야 한다(테스트 포함).
- 서버를 포트 {PORT}로 띄워 직접 확인한다: 재고 부족 409 -> 주문 후 재고 감소 -> 취소 후 재고 복구 -> 리뷰 작성 ->
  같은 품목 두 번째 리뷰 409 -> 남의 리뷰 수정 거부 -> 배송 처리 후 운송장 번호 -> 매출 요약의 객단가 ->
  `Accept-Language: ko` 로 잘못된 입력을 보내 한국어 메시지. 그리고 1차 기능(가입, 로그인, 주문 금액, 취소 409,
  카드 번호 비노출)이 그대로인지. 확인한 뒤 서버는 끈다.
- README.md 를 고친다: 새 API, 바뀐 설정, 손으로 쓴 파일 목록과 각 파일이 하는 일.
