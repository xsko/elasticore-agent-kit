# 과제: 반려동물 쇼핑몰 (Pet Store)
{TOOL_LINE}
이 폴더(비어 있음)에 Spring Boot 4 로 반려동물 쇼핑몰의 서버(REST API)와 간단한 화면을 만든다.

- {LANG_LINE}, Gradle(Gradle wrapper 포함), 데이터베이스는 H2 메모리.
- 이 PC에서 8080 포트는 다른 프로그램이 쓰고 있다. 서버를 띄워 확인할 때는 포트 {PORT}를 쓴다.
- 이 PC에서는 다른 사람의 프로그램(java 등)도 돌고 있다. 프로세스를 이름으로 종료하지 않는다. 직접 띄운 서버는
  그 서버를 띄운 방법으로(예: 백그라운드 작업을 기록해 두고) 끈다.

## 업무

### 1. 카탈로그

- 분류(Category): 이름(1~30자, 필수), 설명(필수). 예: Fish, Dogs, Cats.
- 상품(Product): 이름(1~30자, 필수), 설명(필수), 속한 분류(필수). 예: Angelfish 는 Fish, Bulldog 은 Dogs.
- 판매 품목(Item): 속한 상품(필수), 이름(1~30자, 필수), 설명, 이미지 경로, 단가(0.01 이상, 필수).
  예: Angelfish 의 Large 10.00, Small 8.50.
- 누구나(로그인 없이) 분류·상품·품목을 한 건 조회하고, 이름 일부로 검색할 수 있다. 품목 목록은 페이지 단위, 이름
  오름차순이고 상품으로 골라 볼 수 있다.
- 분류·상품·품목의 등록·수정·삭제는 관리자만 한다.
- 서버가 시작될 때 샘플 카탈로그(분류 3개 이상, 상품 6개 이상, 품목 10개 이상)와 관리자 계정 `admin` / `admin`
  이 들어 있어야 한다.

### 2. 회원

- 회원(Customer): 로그인 ID(1~10자, 필수, 중복 불가), 비밀번호(필수), 이름(firstName, lastName 각 1~50자 필수),
  전화, 이메일(형식 검사), 생년월일(과거 날짜만), 역할(USER / ADMIN, 기본 USER), 집 주소(필수).
- 주소(Address): 거리1(필수), 거리2, 도시(필수), 주/도, 우편번호(필수, 숫자 5자리 또는 `12345-6789` 꼴),
  국가 코드(영문 2자, 필수). 주소는 회원의 집 주소와 주문의 배송지에 같은 모양으로 쓰인다.
- 가입은 누구나 한다. 로그인 ID 가 이미 있으면 409. 로그인과 로그아웃이 있다.
- 자기 정보 조회·수정은 본인만 한다(관리자는 누구의 것이든). 회원 삭제는 관리자만 한다.
- 비밀번호는 해시로만 저장하고 어떤 응답에도 나오지 않는다. 가입자는 스스로 관리자가 될 수 없다 - 역할은
  관리자만 바꾼다(가입 때 ADMIN 을 보내도 USER 로 저장되거나 거부된다).

### 3. 주문

- 로그인한 회원이 자기 주문(PurchaseOrder)을 낸다. 주문 줄(OrderLine)이 1개 이상이어야 한다(비어 있으면 400).
  줄: 품목(필수, 존재하는 품목이어야 한다), 수량(1 이상).
- 줄의 단가는 주문하는 시점의 품목 단가를 복사해 둔다. 나중에 품목 단가가 바뀌어도 이미 낸 주문의 단가와
  금액은 그대로다. 줄 소계 = 단가 x 수량.
- 주문 금액은 모두 서버가 계산한다(클라이언트가 보낸 금액은 무시): 소계 합(totalWithoutVat), VAT 5.5 %
  (vat = 소계 합 x 5.5 %), 할인 2.25 % (discount = (소계 합 + vat) x 2.25 %), 최종 금액
  total = 소계 합 + vat - discount. 비율은 설정 파일에 두고 바꿀 수 있어야 한다.
- 주문 일시는 서버가 정한다. 배송지(주소)는 보내지 않으면 회원의 집 주소다.
- 결제 카드(필수): 카드 번호(필수), 종류(VISA / MASTER_CARD / AMERICAN_EXPRESS, 필수), 만료(`MM/YY` 꼴, 필수).
  카드 번호는 받기만 하고 어떤 응답에도 나오지 않는다.
- 상태: 처음은 PLACED. 관리자가 배송하면 SHIPPED (배송 시각을 서버가 기록). 본인이 취소하면 CANCELLED.
  배송된 주문은 취소할 수 없고(409), 취소된 주문은 배송할 수 없다(409). 삭제는 취소된 주문만, 관리자가 한다.
- 주문은 본인 것만 조회·목록(관리자는 전체). 목록은 최신 주문이 먼저. 목록에서 "아직 배송되지 않은 주문"(배송
  시각이 비어 있는 것)만 골라 볼 수 있어야 한다.
- 주문이 접수·배송·취소될 때마다 서버 로그에 한 줄(주문 번호, 상태, 최종 금액)을 남긴다.

### 4. 관리자 매출 요약

- 관리자만 부르는 API 하나: 상태별 주문 건수와, 취소된 주문을 뺀 매출 합계(total 의 합)를 한 번에 돌려준다.

### 5. 화면

- 서버가 그대로 내주는 정적 HTML + JS 한 장(별도 빌드 도구 없이 동작): 분류별 품목 보기와 검색, 가입, 로그인,
  로그아웃, 장바구니에 담아 주문, 내 주문 목록과 취소, 관리자로 로그인했을 때 주문 배송. 꾸미지 않아도 된다.

### 6. 응답 규칙

- 잘못된 입력 400, 로그인 안 함 401, 권한 없음 403, 없는 것 404, 중복이거나 상태상 할 수 없는 일 409.

## 끝내기 전에

- `./gradlew build` 가 성공해야 한다(테스트 포함).
- 서버를 포트 {PORT}로 띄워 다음을 직접 확인한다: 가입 -> 로그인 -> 카탈로그 조회 -> 주문(금액 계산 확인) ->
  관리자가 품목 단가를 바꿔도 낸 주문의 단가는 그대로 -> 본인 취소 -> 새 주문을 관리자가 배송 -> 배송된 주문 취소
  409 -> 응답에 카드 번호와 비밀번호 없음 -> 로그인 없이 주문 401 -> 다른 회원의 주문 조회 403 또는 404 ->
  로그인 없이 품목 조회는 됨. 확인한 뒤 서버는 끈다.
- README.md 에 실행 방법, 데모 계정, API 목록(메서드, 경로, 예시 curl), 그리고 손으로 쓴 파일 목록과 각 파일이
  하는 일을 쓴다.
