# 변경 요청: 우리 팀 규칙을 생성기에 넣기

이 프로젝트는 도서 대출 API 다(도서 `Book`, 회원 `Member`, 대출 `Loan`).{TOOL_LINE}
우리 팀은 앞으로 만들 모든 프로젝트에 같은 규칙을 쓰려고 한다. 규칙은 생성된 코드를 손으로 고치는 것이 아니라,
**ElastiCORE 가 코드를 만들 때 적용되는 팀 규칙**으로 만든다. 다른 프로젝트에서도 쓸 수 있게 이 프로젝트 안의 **별도
Gradle 모듈**에 둔다.

## 규칙

1. **개인정보 필드:** 모델(YAML)에서 필드에 `@pii` 를 붙이면, 그 필드는 요청으로는 받지만 응답 JSON 에는 절대 나가지
   않는다. 회원의 `email` 에 붙인다. 이메일 중복 검사(같은 이메일로 두 번째 가입은 409)는 그대로 동작해야 한다.
2. **삭제 금지 엔티티:** 엔티티의 `meta` 줄에 `@nodelete` 를 붙이면, 그 엔티티의 REST API 에는 삭제가 없다(단건 삭제도,
   여러 건 삭제도). `Book` 에 붙인다. 회원과 대출의 삭제는 지금처럼 된다.
3. **부분 검색어 길이:** 부분 일치 검색(`@search(like)`) 필드의 검색어는 2글자 이상이어야 한다. 한 글자로 검색하면 400 과
   어느 필드가 틀렸는지 알려 주는 응답, 두 글자 이상이면 지금처럼 검색된다. 검색어를 안 주면 지금처럼 전체 목록이다.
4. **페이지 크기 상한:** 엔티티의 `@expose(n)` 에서 n(한 페이지 크기)이 50 보다 크면 빌드가 실패하고, 어느 엔티티인지
   메시지에 나온다. 지금 모델은 모두 20 이라 빌드는 통과해야 한다.

## 조건

- 생성된 파일을 손으로 고치지 않는다. 모델(YAML)에는 `@pii`, `@nodelete` 표시만 더한다.
- 규칙 모듈에 규칙 단위 테스트를 둔다(규칙 1~3 중 둘 이상). `./gradlew build` 가 테스트까지 통과해야 한다.
- 서버를 포트 {PORT} 에서 띄우고, 규칙 1~3 을 실제 HTTP 호출로 확인한 다음 서버를 끈다. 다른 포트는 쓰지 않는다.
- 끝나면 한국어로 보고한다: 무엇을 만들었는지, 각 규칙을 어떻게 확인했는지(요청과 응답), 확인하지 못한 것.
