# ElastiCORE agent kit

A [Claude Code](https://code.claude.com) plugin for projects built with
[ElastiCORE](https://github.com/xsko/ElastiCORE) - Spring Boot applications generated from a YAML DSL.

Left to itself, an agent edits the generated Java. The next build either overwrites the edit or
stops updating the file from the model, and nobody notices. With this plugin the agent changes the
DSL, regenerates, compiles, and tells you what changed for the business.

[한국어](README.ko.md)

## Install

```bash
claude plugin marketplace add xsko/elasticore-agent-kit
claude plugin install elasticore@elasticore-agent-kit
```

In a session: `/plugin marketplace add xsko/elasticore-agent-kit`, then
`/plugin install elasticore@elasticore-agent-kit`.

To update: `claude plugin marketplace update elasticore-agent-kit`, then
`claude plugin update elasticore@elasticore-agent-kit`, and restart Claude Code.

You need an ElastiCORE 3.0 project. The hooks run in bash: macOS and Linux have it, and on Windows
Claude Code runs hooks with Git Bash. Without bash the hooks do not run; the rest still works.

## What you get

| Part | What it does |
|---|---|
| Skill `elasticore` | Loads when Claude works in an ElastiCORE project. It says how to tell generated files from yours, where a change belongs, the loop (change the DSL, `./gradlew compileJava`, read the generator's warnings), what to ask you first, and how to report. For syntax it sends Claude to the guides ElastiCORE copies into the project. |
| Hooks | Stop hand edits to generated files, say what to run after a DSL change, pass on the generator's warnings, and keep Claude from finishing with a DSL change that was never built. |
| Agent `elasticore:modeler` | Turns a requirement into a DSL change that generates and compiles, and reports it in business terms. |
| Agent `elasticore:reviewer` | Reviews a change: hand edits to generated files, DSL the guides do not know, generated code out of step with the DSL, and who gains or loses what. |
| `/elasticore:generate [task]` | Regenerates and compiles, then explains every warning, skipped file and error, with the DSL fix. |
| `/elasticore:change-report [range]` | Writes what a DSL change means for the business and what needs a decision. |
| `/elasticore:review [range]` | Runs the reviewer on uncommitted changes or a range. |

### The hooks

| When | What happens |
|---|---|
| Claude edits a generated file - first line `//ecd:`, no `Initially generated by ElastiCORE` line, no preserved block | The edit is refused, with where the change belongs instead |
| Claude edits a generated file that has a preserved block (`// !----------` ... `// ------------!`) | Allowed, with a reminder that only the block survives regeneration |
| Claude changes the DSL under `src/main/resources/blueprint` | Told to run `./gradlew compileJava` and fix the warnings before finishing |
| A Gradle build prints `DSL validation warnings:` or reports a hand-edited generated file | Told what that means and what to do |
| Claude is about to finish while a DSL change has not been built | Stopped once and asked to build |

To let Claude edit generated files anyway, set `ELASTICORE_ALLOW_GENERATED_EDITS=1`, for example in
`.claude/settings.local.json`:

```json
{ "env": { "ELASTICORE_ALLOW_GENERATED_EDITS": "1" } }
```

## Keeping up with ElastiCORE

- **The kit holds no DSL reference.** Every generation copies the guides of the ElastiCORE version a
  project uses into its `src/main/resources/blueprint/`, and the skill sends Claude there. When a
  project upgrades ElastiCORE, Claude reads the new guides.
- **What the kit does rely on is tested against ElastiCORE.** The file markers, the generator's
  status lines and warning header, the guide names and the Gradle tasks are checked by
  [`tests/contract/check.py`](tests/contract/check.py): it builds a project with the newest
  ElastiCORE release from Maven Central and generates, edits, breaks and restores it. CI runs it on
  every change and every Monday; a failure names the assumption that no longer holds and where the
  kit states it.

## Develop

```bash
bash tests/hooks/test-hooks.sh                     # the hook script, on the JSON Claude Code sends
python3 tests/contract/check.py                    # JDK 17 and Gradle 8.14 or later on the PATH
claude plugin validate ./plugins/elasticore --strict
claude plugin validate . --strict
claude --plugin-dir ./plugins/elasticore           # try the working copy in an ElastiCORE project
```

`ELASTICORE_VERSION=3.0.261015-alpha1 python3 tests/contract/check.py` checks a given release.
