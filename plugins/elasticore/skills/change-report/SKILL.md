# Change report

1. Get the DSL change: `git diff $ARGUMENTS -- src/main/resources/blueprint`. With no range given,
   use `git diff HEAD -- src/main/resources/blueprint` (staged and unstaged) and add the new YAML
   files that `git status --porcelain -- src/main/resources/blueprint` lists as untracked. Then the
   developer-owned files that changed in the same range - files carrying
   `Initially generated by ElastiCORE`, and hand-written ones.
2. For each construct the diff adds or removes, look up what it means in the project's guides
   (`src/main/resources/blueprint/elasticore-*.md`) rather than guessing.
3. Write the report with the template and the decision table in
   `${CLAUDE_PLUGIN_ROOT}/skills/elasticore/references/change-report.md`. Business words first; a
   reviewer must be able to approve it without reading Java. Use the user's language.
4. If generation has not been run since the change, say so under "Checked" rather than inventing a
   result.
