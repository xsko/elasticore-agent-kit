# Recipe: a library - books, members, loans, rules on other rows, an operation of its own

A complete model for "books, members and loans": create, read, update and search books and members,
an ISBN format rule, a unique e-mail address, loans that name an existing member and book by their
keys, dates the server sets, a rule that refuses a loan when no copy is left (409), returning a loan
as an operation of its own, and a search for the loans not yet returned. Start from
`new-project.md` (build files, wrapper) and use these files instead of its `shop` ones. The agent
kit's contract test generates, builds, starts and calls exactly this project, with every request
shown at the end.

**It needs ElastiCORE 3.0.261021 or later**: a required reference by its key (`Member!`),
`@readonly`, `@search(isnull)`, `@pattern('regex', 'message')` and `ConflictException` came with it.
Take the version as `new-project.md` says - the newest 3.x on Maven Central; when that is
3.0.261020, make the changes of the last section.

It works as written, with `architecture = 'hexagonal'` (the default of `new-project.md`). Rename
`library` and `com.acme.library` together if the task needs another name.

## `src/main/resources/blueprint/library/model/entity.yml`

```yaml
entity:
  Book:
    meta: entity @root @editable @expose(20) @sort(title+) -- book
    fields:
      isbn:       string(13)! @id @pattern('^[0-9]{13}$', 'ISBN must be 13 digits') -- ISBN, 13 digits
      title:      string(200)! @notblank @search(like) -- title
      author:     string(100)! @notblank @search(like) -- author
      pubYear:    int @min(1450) @max(2100) -- publication year
      copies:     int! @min(0) -- copies owned

  Member:
    meta: entity @root @editable @expose(20) @sort(memberId+) @Index(name="uk_member_email", columnList="email", unique=true) -- member
    fields:
      memberId:   long @id @sequence
      name:       string(50)! @notblank -- name
      email:      string(100)! @email -- e-mail address
      joinedAt:   date @readonly -- joined on, set by the server

  Loan:
    meta: entity @root @editable @expose(20) @sort(loanId+) -- loan
    fields:
      loanId:       long @id @sequence
      member:       Member! -- the borrower
      book:         Book! -- the book lent out
      loanDate:     date @readonly -- lent on, set by the server
      dueDate:      date @readonly -- due back, loan date + 14
      returnedDate: date @readonly @search(isnull) -- returned on, empty until returned
```

Why each piece is there:

- `isbn` is a key the client sends (no `@sequence`). `@pattern('^[0-9]{13}$', 'ISBN must be 13
  digits')` answers 400 with that message in `fieldErrors` when the value does not match. Write a
  backslash doubled (`\\d`), or use `[0-9]`. A create with an ISBN that exists answers 409.
- `@Index(name="uk_member_email", columnList="email", unique=true)` on the entity line makes the
  e-mail unique: a second member with the same address answers 409.
- `member: Member!` and `book: Book!` make a loan carry `memberId` and `bookIsbn` - the target's key
  names - in requests and answers, and the `!` makes them required: 400 without them. An answer also
  carries the nested `member` and `book`; a request does not need them.
- `@readonly` marks a value the server sets: it is in answers, never taken from a request, and not
  required. `beforeSave` fills it (below). An answer leaves out a field that is empty, so
  `returnedDate` appears once the loan is returned.
- `@search(isnull)` gives the loan search `"returnedDateEmpty"`: `true` finds the loans not yet
  returned, `false` the returned ones; without it, both.
- `@search(like)` searches by part of the title or the author. There is no `@EnableJpaAuditing` on
  the application class: this model has no `CreatedDate` field.

## Generate, then add the rules and the operation

Run `./gradlew compileJava` once. It writes, among the rest,
`src/main/java/com/acme/library/application/LoanService.java` and `MemberService.java` next to it.
Both are yours: their second line starts with `// Initially generated by ElastiCORE;`, and the
generator never touches them again. Add these methods inside each class, before its last `}` - the
names are written in full, so they need no imports:

## Add to `LoanService.java`

```java
    /** A new loan: the dates are the server's, and a book with no copy left cannot be lent (409). */
    @Override
    protected void beforeSave(com.acme.library.domain.model.Loan entity,
                              com.acme.library.application.dto.LoanDTO request) {
        if (entity.getLoanId() == null) {
            com.acme.library.domain.model.Book book =
                    entityManager.find(com.acme.library.domain.model.Book.class, request.getBookIsbn());
            if (book == null) {
                throw new jakarta.persistence.EntityNotFoundException("Book " + request.getBookIsbn() + " not found");
            }
            if (entityManager.find(com.acme.library.domain.model.Member.class, request.getMemberId()) == null) {
                throw new jakarta.persistence.EntityNotFoundException("Member " + request.getMemberId() + " not found");
            }
            long out = entityManager.createQuery(
                    "select count(l) from Loan l where l.book.isbn = :isbn and l.returnedDate is null", Long.class)
                    .setParameter("isbn", book.getIsbn()).getSingleResult();
            if (out >= book.getCopies()) {
                throw new io.elasticore.springboot3.validation.ConflictException(
                        "No copies of book " + book.getIsbn() + " left: " + out + " of " + book.getCopies() + " are on loan");
            }
            entity.setLoanDate(java.time.LocalDate.now());
            entity.setDueDate(entity.getLoanDate().plusDays(14));
        }
        super.beforeSave(entity, request);
    }

    /** Return a loan: records today's date once; a second return is refused (409). */
    @org.springframework.transaction.annotation.Transactional
    public com.acme.library.application.dto.LoanDTO returnLoan(Long loanId) {
        com.acme.library.domain.model.Loan loan = entityManager.find(com.acme.library.domain.model.Loan.class, loanId);
        if (loan == null) {
            throw new jakarta.persistence.EntityNotFoundException("Loan " + loanId + " not found");
        }
        if (loan.getReturnedDate() != null) {
            throw new io.elasticore.springboot3.validation.ConflictException(
                    "Loan " + loanId + " was already returned on " + loan.getReturnedDate());
        }
        loan.setReturnedDate(java.time.LocalDate.now());
        entityManager.flush();
        return findById(loanId).orElseThrow();
    }
```

## Add to `MemberService.java`

```java
    /** The joining date is the server's. */
    @Override
    protected void beforeSave(com.acme.library.domain.model.Member entity,
                              com.acme.library.application.dto.MemberDTO request) {
        if (entity.getJoinedAt() == null) {
            entity.setJoinedAt(java.time.LocalDate.now());
        }
        super.beforeSave(entity, request);
    }
```

`beforeSave` runs on create and on update; `getLoanId() == null` means a create, since the key is
`@sequence`. It sets the dates on the entity: a `@readonly` field is never copied from the request,
so an update keeps the stored dates. `entityManager` is a field of the service - `find` reads a row,
`createQuery` counts. `ConflictException` answers 409 and `EntityNotFoundException` 404, each with
your message as `detail`.

`returnLoan` is the operation the generated CRUD does not have. It changes the loan in a
transaction and answers it as `GET /api/library/loan/{loanId}` does. Then write the one controller
of your own that calls it - a new file, no ElastiCORE header:

## `src/main/java/com/acme/library/adapter/in/web/LoanReturnController.java`

```java
package com.acme.library.adapter.in.web;

import com.acme.library.application.LoanService;
import com.acme.library.application.dto.LoanDTO;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

/** The one business operation the generated CRUD does not have: returning a loan. */
@RestController
@RequestMapping("/api/library/loan")
public class LoanReturnController {

    private final LoanService service;

    public LoanReturnController(LoanService service) {
        this.service = service;
    }

    @PostMapping("/{loanId}/return")
    public LoanDTO returnLoan(@PathVariable Long loanId) {
        return service.returnLoan(loanId);
    }
}
```

It goes in the package of the generated controllers, `adapter/in/web`: the generated
`LibraryApiErrors` answers for the controllers of its own package, so the 404 and 409 of
`returnLoan` come back as the same problem body as every other refusal. Then build again
(`./gradlew bootJar`): the generator reports both services `SKIP(user-owned)` and keeps the methods,
and leaves the controller alone. Do not write the services before the first generation - a file
without the ElastiCORE header is reported `SKIP(no ElastiCORE header)`, and the advice for that is
to delete it.

A project first generated with an ElastiCORE older than 3.0.261021 has a `<Domain>ApiErrors.java`
without the handler for `ConflictException`, so the exception is not answered with 409. That file
is generated once and is yours: add the handler to it, next to the one for `BadRequestException`:

```java
    @ExceptionHandler(io.elasticore.springboot3.validation.ConflictException.class)
    public ProblemDetail conflict(io.elasticore.springboot3.validation.ConflictException ex) {
        return problem(HttpStatus.CONFLICT, "conflict", "Conflicts with stored data", ex.getMessage());
    }
```

## The API it generates, and the operation added

Base paths `/api/library/book`, `/api/library/member` and `/api/library/loan`. JSON in and out;
dates are `yyyy-MM-dd`. A refusal is a problem body with `status`, `code` and `detail`; a 400 for
invalid input also has `fieldErrors`, naming each field. A book is
`{"isbn":"9780000000001","title":"Dune","author":"Frank Herbert","pubYear":1965,"copies":1}` below.

| Operation | Request | Answer |
|---|---|---|
| Create a book | `POST /api/library/book` with a book | 200, the book |
| An ISBN of 12 or 14 digits, or with a letter | `POST /api/library/book` `{"isbn":"978000000000",...}` | 400, `fieldErrors`: `isbn`, "ISBN must be 13 digits" |
| An ISBN that exists | the same book again | 409, `code` `already-exists` |
| Invalid book | an empty `title`, a `title` of 201 characters, `pubYear` 1449 or 2101, `copies` -1, no `author` | 400 each |
| Read one | `GET /api/library/book/9780000000001` | 200; unknown ISBN 404 |
| Update | `PUT /api/library/book` with every field, the `isbn` in the body | 200, the book |
| List, by title | `POST /api/library/book/search` `{"pageNumber":0,"pageSize":2}` | 200, a page in title order: `content`, `totalElements`, ... |
| Search | `POST /api/library/book/search` `{"title":"mma"}`, `{"author":"Orwell"}` | 200, the books whose title or author contains it |
| Join | `POST /api/library/member` `{"name":"Kim","email":"kim@example.com"}` | 200 with `memberId` and `joinedAt` today; a `joinedAt` in the request is ignored |
| Invalid or taken e-mail | `{"name":"Lee","email":"not-an-email"}`; another member with `kim@example.com` | 400; 409, `code` `unique` |
| Member: read, update, list | `GET /api/library/member/1`; `PUT /api/library/member` `{"memberId":1,"name":"Kim Updated","email":"kim@example.com"}`; `POST /api/library/member/search` `{}` | 200 each |
| Lend | `POST /api/library/loan` `{"memberId":1,"bookIsbn":"9780000000001"}` | 200 with `loanId`, `loanDate` today, `dueDate` today + 14 and no `returnedDate`; dates in the request are ignored |
| Lend without `memberId` | `{"bookIsbn":"9780000000001"}` | 400, `fieldErrors`: `memberId` |
| Unknown member or book | `{"memberId":999999,"bookIsbn":"9780000000001"}`; `{"memberId":1,"bookIsbn":"9999999999999"}` | 404, `detail` "Member 999999 not found"; "Book 9999999999999 not found" |
| No copy left | a second loan of a book with 1 copy; a loan of a book with 0 | 409, `code` `conflict`, `detail` "No copies of book 9780000000001 left: 1 of 1 are on loan" |
| Return | `POST /api/library/loan/1/return` | 200, the loan with `returnedDate` today; the copy can be lent again |
| Return again | the same request | 409, `detail` "Loan 1 was already returned on " and the date |
| Return an unknown loan | `POST /api/library/loan/987654/return` | 404, `detail` "Loan 987654 not found" |
| A member's loans | `POST /api/library/loan/search` `{"memberId":1}` | 200, a page of that member's loans |
| Not yet returned | `POST /api/library/loan/search` `{"memberId":1,"returnedDateEmpty":true}`; `false` for the returned ones | 200, those loans |
| A book's loans | `POST /api/library/loan/search` `{"bookIsbn":"9780000000001"}` | 200, a page of that book's loans |

```bash
curl -s -X POST localhost:PORT/api/library/loan -H 'Content-Type: application/json' \
     -d '{"memberId":1,"bookIsbn":"9780000000001"}'
curl -s -X POST localhost:PORT/api/library/loan/1/return
curl -s -X POST localhost:PORT/api/library/loan/search -H 'Content-Type: application/json' -d '{"returnedDateEmpty":true}'
```

There is no `GET` for a list: lists and searches are `POST .../search`. The whole API, with every
field, is at `http://localhost:PORT/v3/api-docs` once the server runs.

## On ElastiCORE 3.0.261020

Write the same project with the changes below; `@readonly` stays - for these dates, which are not
required, it already keeps a request's values out there. This variant was built and called by hand
with 3.0.261020-alpha2; the contract test does not build it.

- `member: Member` and `book: Book`, without the `!`: there the `!` makes the generated DTO require
  the nested object instead of the key, and every loan is refused. Make the keys required as
  `recipe-board.md` does, first thing in the `getLoanId() == null` branch of `beforeSave`:
  `if (request.getMemberId() == null) throw new io.elasticore.springboot3.validation.BadRequestException("memberId: required");`
  and the same for `bookIsbn`.
- No `@pattern` that works: the form with the message after the regex generates no check, and
  `@pattern(regexp="...", message="...")` does not compile. Leave it off `isbn` and check it in a
  `beforeSave` in `BookService.java`:
  `if (request.getIsbn() == null || !request.getIsbn().matches("[0-9]{13}")) throw new io.elasticore.springboot3.validation.BadRequestException("isbn: ISBN must be 13 digits");`
  It answers 400 with that `detail` and no `fieldErrors`.
- No `ConflictException`: throw `org.springframework.dao.DataIntegrityViolationException` with the
  same message. It answers 409 too, but its `detail` is "A unique value is already taken, or the
  row is still referenced by another." instead of your message.
- No `@search(isnull)` - there it searches for an equal value. Leave it off `returnedDate` and
  search with a hand-written condition, `Q.Loan.returnedDate(Op.IS_NULL, null)`: a method in
  `LoanService`, and an operation for it in `LoanReturnController`:

  ```java
      /** The loans not yet returned that match the search. */
      public org.springframework.data.domain.Page<com.acme.library.application.dto.LoanDTO> searchOpen(
              com.acme.library.application.dto.LoanSrchDTO search) {
          return query.findAll(com.acme.library.application.dto.LibraryMapper.toSpec(search)
                          .and(com.acme.library.domain.model.Q.Loan.returnedDate(io.elasticore.springboot3.entity.Op.IS_NULL, null)),
                          search.getPageable())
                  .map(com.acme.library.application.dto.LibraryMapper::toDTO);
      }
  ```

  ```java
      @PostMapping("/search/open")
      public org.springframework.data.domain.Page<LoanDTO> searchOpen(
              @org.springframework.web.bind.annotation.RequestBody com.acme.library.application.dto.LoanSrchDTO search) {
          return service.searchOpen(search);
      }
  ```

  `POST /api/library/loan/search/open` with a search body, such as `{"memberId":1}`, then answers a
  page of the loans not yet returned.
