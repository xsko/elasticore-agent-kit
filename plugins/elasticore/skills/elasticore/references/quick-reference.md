# ElastiCORE DSL quick reference (3.0 rule engine, `hexagonal` or `ddd`)

For a build whose `elasticore { }` block sets `architecture = 'hexagonal'` or `'ddd'` - the
template of `new-project.md` does. Without that block the 2.x generator runs, and much of this page
does not apply (SKILL.md section 3).

Everyday work needs only this page and a recipe (`recipe-board.md`). Open the project's long guides
(`src/main/resources/blueprint/elasticore-*.md`) only for something this page does not have. Every
line in the sample at the end is generated, compiled and called by the agent kit's CI.

## Where things go

| File | What |
|---|---|
| `src/main/resources/blueprint/<domain>/env.yml` | domain name, base package (copy it from a recipe) |
| `src/main/resources/blueprint/<domain>/model/*.yml` | entities and enums - the part you write |
| `src/main/java/.../<Entity>Service.java` | your logic - its first line is `//ecd:...` and its second starts with `// Initially generated by ElastiCORE;`, which makes it yours |
| everything else generated | do not edit; change the YAML and build again |

`./gradlew compileJava` generates and then compiles. `./gradlew bootJar` also packages. To run the
application, see `run-and-check.md` - never `./gradlew bootRun` from a tool's shell.

## A field: `name: type [annotations] -- label`

| Write | Means |
|---|---|
| `string(100)` | text, at most 100 characters |
| `string(100)!` | required - but `""` still passes |
| `string(100)! @notblank` | required and not empty or blank |
| `string(20)! @length(min=4)` | 4 to 20 characters |
| `text! @notblank` | long text, required, not blank |
| `string(100) @email` | an e-mail address |
| `int @min(1) @max(10)` | a whole number from 1 to 10 |
| `long`, `int`, `boolean`, `date`, `datetime`, `money(10.2)` | the other types; `datetime` is `"yyyy-MM-dd HH:mm:ss"` in JSON |
| `kind: ItemKind` | an enum of the model (an `enumeration:` entry) |
| `post: Post` | a reference to another root: requests and answers carry its id field; no `!` on it (see the recipe) |
| `-- product name` | the label: column comment and API description |

The id field of a reference is the field name plus the target's key name, unless the key already
starts with the field name: `post: Post` (key `postId`) carries `postId`; `author: Member` (key
`memberId`) carries `authorMemberId`.

Not types: `uuid`, `short`, `char`, `OffsetDateTime`. Use `string(36)` for a uuid, `int` for a
short, `string(1)` for a char, `timestamp` (an instant, ISO-8601 in JSON) for an offset time.

YAML: a label with `: ` in it breaks the file (`* LOAD ERROR:` in the build output, and the whole
file is left out); ` #` cuts the label off there. Write `-- title, required`, not `-- title: required`.

## Keys

| Write | Means |
|---|---|
| `postId: long @id @sequence` | numbered by the database; leave it out when creating |
| `code: string(15) @id @genid` | a random key (3-letter prefix and 12 letters and digits) |

## The entity line: `meta: entity @root @editable @expose(20) @sort(postId-) -- label`

| Annotation | Means |
|---|---|
| `@root` | an entity with its own API and repository |
| `@editable` | it can be updated (`PUT`); without it a root has no update, and its fields go to a generated `XxxBase` class |
| `@expose(20)` | the REST API; 20 is the page size |
| `@sort(postId-)` | the default order of lists: `-` descending, `+` ascending |
| `@search(like)` on a field | search by part of the value (case-sensitive; `@search(%__%)` ignores case); other text fields match the whole value unless it starts or ends with `%`; date fields are searched with `<field>From` and `<field>To` |

## The API of an `@expose` entity

Base path `/api/<domain>/<entity>` - the entity name with a small first letter: `PurchaseOrder` is
`/api/shop/purchaseOrder`.

| Request | Does |
|---|---|
| `POST /` with the fields | create; answers the row with its key |
| `GET /{key}` | read one; 404 when there is none |
| `PUT /` with the key **in the body** | update (needs `@editable`) |
| `DELETE /{key}` | delete; answers `true` |
| `POST /search` with `{field: value, "pageNumber": 0, "pageSize": 20, "sortCode": "title+"}` | a page: `content`, `totalElements`, `totalPages`, `number` |

There is no `GET` for a list. `pageNumber` starts at 0. Invalid input answers 400 with `fieldErrors`;
a row still referenced answers 409.

## Time stamps

```yaml
createdAt:  datetime @updatable(false) @jpa:org.springframework.data.annotation.CreatedDate -- written at
modifiedAt: datetime @jpa:org.springframework.data.annotation.LastModifiedDate -- changed at
```

They are set by the server and never taken from a request - only with `@EnableJpaAuditing`
(`org.springframework.data.jpa.repository.config.EnableJpaAuditing`) on the application class.
There is no `@createtime`.

## Your own logic and checks

Put it in `<Entity>Service` (it extends `<Entity>CoreService`). Override:

```java
@Override
protected void beforeSave(Post entity, PostDTO request) {   // runs on create and on update
    if (entity.getPostId() == null) { /* only on create - with an @id @sequence key */ }
    super.beforeSave(entity, request);
}
```

Add the method to the generated `<Entity>Service.java` after the first generation - do not write
that file yourself before it exists.

Throw `jakarta.persistence.EntityNotFoundException` for 404 and
`io.elasticore.springboot3.validation.BadRequestException` for 400; the generated error handler
answers them. Do not write controllers, DTOs, repositories, security or error handlers by hand -
they are generated.

## Names to avoid

- Entity and enum names that are also annotations the generated code uses, when they cross a domain
  or are a DTO field's type: `Comment` from another domain, `Size`, `Schema`, `Setter`, `Column`, `Id`.
- Entity names that are SQL words, since the entity name becomes the table name: `Order`, `User`,
  `Group` - use `PurchaseOrder`, `Member`, `Team`.
- SQL words as field names: `order`, `group`, `user`, `select`, `from`, `where`, `table`, `index`,
  `key`, `value`.

## After every change

1. `./gradlew compileJava`, and read the whole output.
2. Fix each line under `[elcore3] DSL validation warnings:` and each `* LOAD ERROR:` in the YAML.
3. A compile error in a generated file is fixed in the YAML too - never in that file.

## `src/main/resources/blueprint/board/model/sample.yml`

```yaml
enumeration:
  ItemKind:
    meta: enum @db(code) @json(code) -- item kind
    fields:
      code:  string(1) @code
      label: string(20)
    enum:
      BOOK:  B, Book
      MUSIC: M, Music

entity:
  Item:
    meta: entity @root @editable @expose(20) @sort(name+) -- item
    fields:
      itemCode:   string(15) @id @genid
      name:       string(100)! @notblank @search(like) -- name
      handle:     string(20)! @length(min=4) -- handle
      memo:       string(50)! -- memo, required - and an empty one passes
      contact:    string(100) @email -- contact address
      rating:     int @min(1) @max(10) -- rating
      price:      money(10.2) -- price
      releasedOn: date -- release date
      inStock:    boolean -- in stock
      kind:       ItemKind -- kind
      createdAt:  datetime @updatable(false) @jpa:org.springframework.data.annotation.CreatedDate -- written at
      modifiedAt: datetime @jpa:org.springframework.data.annotation.LastModifiedDate -- changed at
```
