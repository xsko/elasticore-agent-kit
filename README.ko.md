# ElastiCORE agent kit

[ElastiCORE](https://github.com/xsko/ElastiCORE)로 만든 프로젝트(YAML DSL에서 생성하는 Spring Boot 애플리케이션)를 위한
[Claude Code](https://code.claude.com) 플러그인입니다.

그냥 두면 에이전트는 생성된 Java를 고칩니다. 다음 빌드가 그 수정을 덮어쓰거나, 그 파일이 더 이상 모델을 따라가지 않게 되는데
아무도 모르고 지나갑니다. 이 플러그인을 쓰면 에이전트는 DSL을 고치고, 다시 생성하고, 컴파일한 뒤 업무에 무엇이 바뀌었는지 알려 줍니다.

[English](README.md)

## 설치

```bash
claude plugin marketplace add xsko/elasticore-agent-kit
claude plugin install elasticore@elasticore-agent-kit
```

세션 안에서는 `/plugin marketplace add xsko/elasticore-agent-kit` 다음 `/plugin install elasticore@elasticore-agent-kit`.

업데이트: `claude plugin marketplace update elasticore-agent-kit`, `claude plugin update elasticore@elasticore-agent-kit`
후 Claude Code를 다시 시작합니다.

ElastiCORE 3.0 프로젝트가 필요합니다. hook은 bash로 돕니다. macOS와 Linux에는 기본으로 있고, Windows에서는 Claude Code가
Git Bash로 hook을 실행합니다. bash가 없으면 hook만 빠지고 나머지는 그대로 동작합니다.

## 들어 있는 것

| 구성 | 하는 일 |
|---|---|
| skill `elasticore` | ElastiCORE 프로젝트에서 일할 때 불려 옵니다. 생성 파일과 내 파일을 가리는 법, 변경이 들어갈 자리, 작업 순서(DSL 수정 → `./gradlew compileJava` → 생성기 경고 확인), 먼저 물어볼 일, 보고 방법을 담습니다. 문법은 ElastiCORE가 프로젝트에 복사해 둔 가이드를 읽게 합니다. |
| hook | 생성 파일 직접 수정을 막고, DSL을 고친 뒤 실행할 것을 알려 주고, 생성기 경고를 전하고, 빌드하지 않은 DSL 변경을 둔 채 끝내지 않게 합니다. |
| agent `elasticore:modeler` | 요구사항을 생성·컴파일이 되는 DSL 변경으로 바꾸고, 업무 말로 보고합니다. |
| agent `elasticore:reviewer` | 변경을 검토합니다: 생성 파일 손수정, 가이드에 없는 DSL, DSL과 어긋난 생성 코드, 누가 무엇을 얻고 잃는지. |
| `/elasticore:generate [태스크]` | 다시 생성하고 컴파일한 뒤 경고·건너뛴 파일·오류를 DSL 고치는 법과 함께 설명합니다. |
| `/elasticore:change-report [범위]` | DSL 변경이 업무에 뜻하는 것과 결정이 필요한 것을 씁니다. |
| `/elasticore:review [범위]` | 커밋하지 않은 변경이나 지정한 범위를 reviewer로 검토합니다. |

### hook

| 언제 | 무슨 일 |
|---|---|
| 생성 파일을 고치려 할 때 - 첫 줄이 `//ecd:`이고 `Initially generated by ElastiCORE` 줄도 보존 블록도 없는 파일 | 막고, 대신 어디를 고쳐야 하는지 알려 줍니다 |
| 보존 블록(`// !----------` ... `// ------------!`)이 있는 생성 파일을 고칠 때 | 허용하되, 블록 안만 재생성 뒤에도 남는다고 알려 줍니다 |
| `src/main/resources/blueprint`의 DSL을 고쳤을 때 | 끝내기 전에 `./gradlew compileJava`를 돌리고 경고를 고치라고 알려 줍니다 |
| Gradle 출력에 `DSL validation warnings:`나 손으로 고친 생성 파일이 나올 때 | 그 뜻과 할 일을 알려 줍니다 |
| 빌드하지 않은 DSL 변경을 둔 채 끝내려 할 때 | 한 번 붙잡고 빌드하라고 합니다 |

그래도 생성 파일을 고치게 하려면 `ELASTICORE_ALLOW_GENERATED_EDITS=1`을 설정합니다. 예: `.claude/settings.local.json`

```json
{ "env": { "ELASTICORE_ALLOW_GENERATED_EDITS": "1" } }
```

## ElastiCORE 변화 따라가기

- **kit에는 DSL 문법을 넣지 않습니다.** ElastiCORE는 생성할 때마다 그 프로젝트가 쓰는 버전의 가이드를
  `src/main/resources/blueprint/`에 복사하고, skill은 Claude를 그곳으로 보냅니다. 프로젝트가 ElastiCORE를 올리면 Claude는 새 가이드를 읽습니다.
- **kit이 기대는 ElastiCORE 동작은 실제 빌드로 검사합니다.** 파일 표시, 생성 상태 문구, 경고 머리말, 가이드 이름, Gradle 태스크를
  [`tests/contract/check.py`](tests/contract/check.py)가 Maven Central의 최신 ElastiCORE로 프로젝트를 만들어 생성·수정·고장·복구해 보며 확인합니다.
  CI가 변경마다, 그리고 매주 월요일에 돌리고, 실패하면 깨진 가정과 kit에서 그 가정을 적은 곳을 알려 줍니다.

## 개발

```bash
bash tests/hooks/test-hooks.sh                     # Claude Code가 보내는 JSON으로 hook 스크립트 검사
python3 tests/contract/check.py                    # PATH에 JDK 17, Gradle 8.14 이상
claude plugin validate ./plugins/elasticore --strict
claude plugin validate . --strict
claude --plugin-dir ./plugins/elasticore           # 작업 중인 플러그인을 ElastiCORE 프로젝트에서 시험
```

`ELASTICORE_VERSION=3.0.261015-alpha1 python3 tests/contract/check.py`로 특정 릴리스를 검사합니다.
