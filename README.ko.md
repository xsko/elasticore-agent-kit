# ElastiCORE agent kit

[ElastiCORE](https://github.com/xsko/ElastiCORE)로 만든 프로젝트(YAML DSL에서 생성하는 Spring Boot 애플리케이션)를 위한
[Claude Code](https://code.claude.com) 플러그인입니다.

그냥 두면 에이전트는 생성된 Java를 고칩니다. 다음 빌드가 그 수정을 덮어쓰거나, 그 파일이 더 이상 모델을 따라가지 않게 되는데
아무도 모르고 지나갑니다. 이 플러그인을 쓰면 에이전트는 DSL을 고치고, 다시 생성하고, 컴파일한 뒤 업무에 무엇이 바뀌었는지 알려 줍니다.

[English](README.md)

## 설치

```bash
claude plugin marketplace add xsko/elasticore-agent-kit
claude plugin install elasticore@elasticore-agent-kit
```

세션 안에서는 `/plugin marketplace add xsko/elasticore-agent-kit` 다음 `/plugin install elasticore@elasticore-agent-kit`.

이미 있는 ElastiCORE 3.0 프로젝트에서 쓰고, 새 프로젝트도 시작합니다. "ElastiCORE로" 애플리케이션을 만들어 달라고 하면 Claude는
Maven Central의 릴리스와, CI가 매주 실제로 빌드하는 템플릿으로 프로젝트를 만듭니다. ElastiCORE를 소스에서 빌드하거나 PC의 다른
프로젝트를 뒤지지 않습니다.

hook은 bash로 돕니다. macOS와 Linux에는 기본으로 있고, Windows에서는 Claude Code가 Git Bash로 hook을 실행합니다.
Git Bash가 없는 Windows에서는 편집·명령마다 hook 오류가 표시되니, Git for Windows를 설치하거나 플러그인을 끄세요.

## 업데이트

Claude Code는 이런 마켓플레이스의 플러그인을 저절로 업데이트하지 않습니다. 최신 버전은 이렇게 받습니다.

```bash
claude plugin marketplace update elasticore-agent-kit
claude plugin update elasticore@elasticore-agent-kit
```

그다음 Claude Code 세션을 새로 시작하거나, 열려 있는 세션에서 `/reload-plugins`를 실행합니다.
설치된 버전은 `claude plugin list`로 보고, 바뀐 내용은 [CHANGELOG.md](CHANGELOG.md)에 있습니다.

세션 안에서는 `/plugin` → **Installed** 탭 → `elasticore` → **Update now**. 자동으로 받으려면 `/plugin` → **Marketplaces** 탭 →
`elasticore-agent-kit` → **Enable auto-update**. 그러면 세션을 시작할 때 업데이트되고, 다음 세션부터 새 버전이 적용됩니다.

## 들어 있는 것

| 구성 | 하는 일 |
|---|---|
| skill `elasticore` | ElastiCORE 프로젝트에서 일하거나 새로 시작할 때 불려 옵니다. 프로젝트 시작 방법, 빌드가 어느 생성기를 쓰고 각각 무엇을 지원하는지, 생성 파일과 내 파일을 가리는 법, 변경이 들어갈 자리, 작업 순서(DSL 수정 → `./gradlew compileJava` → 생성기 경고 확인), 먼저 물어볼 일, 보고 방법을 담습니다. 문법은 ElastiCORE가 프로젝트에 복사해 둔 가이드를 읽게 합니다. |
| hook | 생성 파일 수정과 `-Pforce` 실행을 막고, DSL을 고친 뒤 실행할 것을 알려 주고, 생성기 경고를 전하고, 성공한 빌드로 생성되지 않은 DSL 변경을 둔 채 끝내지 않게 합니다. |
| agent `elasticore:modeler` | 요구사항을 생성·컴파일이 되는 DSL 변경으로 바꾸고, 업무 말로 보고합니다. |
| agent `elasticore:reviewer` | 변경을 검토합니다: 생성 파일 손수정, 가이드나 생성기가 모르는 DSL, DSL과 어긋난 생성 코드, 누가 무엇을 얻고 잃는지. |
| `/elasticore:generate [태스크]` | 다시 생성하고 컴파일한 뒤 경고·건너뛴 파일·오류를 DSL 고치는 법과 함께 설명합니다. |
| `/elasticore:change-report [범위]` | DSL 변경이 업무에 뜻하는 것과 결정이 필요한 것을 씁니다. |
| `/elasticore:review [범위] [full]` | 커밋하지 않은 변경이나 지정한 범위를 reviewer로 검토합니다. 읽기만 하고, `full`을 붙이면 빌드까지 합니다(파일이 다시 생성됨). |

### hook

| 언제 | 무슨 일 |
|---|---|
| 편집 도구로 생성 파일을 고치려 할 때 - 첫 줄이 `//ecd:`이고 `// Initially generated by ElastiCORE;` 줄도 보존 블록도 없는 파일 | 막고, 대신 어디를 고쳐야 하는지 알려 줍니다. 보존 블록(`// !----------` ... `// ------------!`) 하나를 통째로 넣는 수정은 허용 |
| 생성할 때마다 다시 쓰는 파일을 고치려 할 때 - `blueprint/schema.yml`, 복사된 가이드, 기본 `i18n/<도메인>-messages.properties` | 막습니다 |
| 보존 블록이 있는 생성 파일을 고칠 때 | 허용하되, 블록 안만 재생성 뒤에도 남는다고 알려 줍니다 |
| Gradle을 `-Pforce`로 실행하려 할 때 | 막습니다: 손으로 고친 내용을 덮어씁니다. 결정은 사용자가 합니다 |
| `src/main/resources/blueprint/<도메인>/`의 모델을 고쳤을 때 | 끝내기 전에 `./gradlew compileJava`를 돌리고 경고를 고치라고 알려 줍니다. `elasticore { }` 블록이 없는 빌드면 2.x 생성기가 접근 규칙·생명주기·계산 값을 무시한다는 것도 알려 줍니다 |
| Gradle 출력에 DSL 검증 경고나 손으로 고친 생성 파일이 나올 때 | 그 뜻과 할 일을 알려 줍니다 |
| 성공한 빌드로 생성되지 않은 DSL 변경을 둔 채 끝내려 할 때 | 한 번 돌려보내 빌드하게 합니다. 백그라운드 빌드, 잘리거나 걸러진 출력은 빌드로 치지 않습니다 |

hook은 편집 도구와 Gradle 실행을 봅니다. Bash로 스크립트를 돌려 고치는 것은 막지 못하며, skill이 그렇게 하지 말라고 안내합니다.

그래도 생성 파일을 고치게 하려면 `ELASTICORE_ALLOW_GENERATED_EDITS=1`, `-Pforce`를 허용하려면 `ELASTICORE_ALLOW_FORCE=1`을
설정합니다. 예: `.claude/settings.local.json`

```json
{ "env": { "ELASTICORE_ALLOW_GENERATED_EDITS": "1" } }
```

## ElastiCORE 변화 따라가기

- **kit에는 DSL 문법을 넣지 않습니다.** ElastiCORE는 생성할 때마다 그 프로젝트가 쓰는 버전의 가이드를
  `src/main/resources/blueprint/`에 복사하고, skill은 Claude를 그곳으로 보냅니다. 프로젝트가 ElastiCORE를 올리면 Claude는 새 가이드를 읽습니다.
- **kit이 기대는 ElastiCORE 동작은 실제 빌드로 검사합니다.** 새 프로젝트 템플릿과 예제, 파일 표시, 두 생성기의 상태 문구와 경고
  머리말, 가이드 이름, Gradle 태스크, 띄운 애플리케이션의 응답을 [`tests/contract/check.py`](tests/contract/check.py)가 확인합니다.
  Maven Central의 최신 ElastiCORE 3로 템플릿·예제·2.x 생성기 프로젝트를 만들어 생성·수정·고장·복구·실행해 봅니다.
  CI가 변경마다, 그리고 매주 월요일에 돌리고, 실패하면 깨진 가정과 kit에서 그 가정을 적은 곳을 알려 줍니다.

## 개발

```bash
bash tests/hooks/test-hooks.sh                     # Claude Code가 보내는 JSON으로 hook 스크립트 검사 (HOOK_BASH=/bin/bash로 셸 지정)
python3 tests/contract/check.py                    # PATH에 JDK 17, Gradle 8.14 이상
claude plugin validate ./plugins/elasticore --strict
claude plugin validate . --strict
claude --plugin-dir ./plugins/elasticore           # 작업 중인 플러그인을 ElastiCORE 프로젝트에서 시험
```

`ELASTICORE_VERSION=3.0.261015-alpha1 python3 tests/contract/check.py`로 특정 릴리스를 검사합니다.
